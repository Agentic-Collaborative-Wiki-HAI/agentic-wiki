# Native app compared with released Prototype
Read-only implementation audit, 2026-11-17. Code checkpoint: `f2519f4`, including N4–N6. The design baseline is the released Prototype page `1469:30533` in Figma file `fm5zX32mbG13hahShVgJwd`, whose 246 top-level frame identities were checked during implementation planning. No Figma page, component or comment was changed in this audit.

## Assessment
The app implements the core data/review boundaries, but its interface is only partially aligned with Prototype. The largest differences concern page composition, passage-relative notes, dedicated Search/History views, recording structure and authoring controls. Those are not resolved by passing the functional tests. The current build also makes useful local-app choices—connection settings, explicit source imports and recoverable unpublished drafts—which should be retained rather than removed to imitate a static frame.

The immediate recommendation is a bounded shell, annotation and keyboard-accessibility pass before adding more capabilities. Full recording, semantic retrieval, Maintenance and shared operation remain separate workstreams. This report proposes corrections; it does not authorize or implement them.

## Method and coverage
Compared live rendered Prototype boards directly because there is no complete current implementation specification for these routes. Captured 21 native states in disposable fictional workspaces, inspected layout geometry at 1800, 1440 and 980 CSS-pixel widths, exercised independent ToC controls, and ran diagnostic 320-pixel reflow, 200% text enlargement and text-spacing checks. Selected screenshots were inspected visually. Native functional regression suites separately verified the complete passage-review and Chat/draft journeys; see [Chat QA](app-chat-qa-2026-11-17.md).

The accessibility pass read the macOS accessibility tree for read, search, proposal and history states. Targeted actual native key events checked tabs, an inline citation and Chat focus/escape. An earlier synthetic key probe did not perform native Tab defaults and is not used as evidence. Temporary focus loss was recovered before the native key checks. No VoiceOver listening session or complete assistive-technology audit was performed.

Evidence images and machine output are outside Git. Native audit captures are identified below by filename; `findings.json` contains region measurements, `keyboard-native.json` records actual key results, and four `.ax.json` captures contain macOS roles/names/states. They contain fictional test content. A failing intermediate audit harness capture is not part of the completed evidence set.

## What already follows the design
- Wiki-tree and page-contents controls are separate, with the tree icon reserved for wiki navigation. The recording is a child of Getting started; switching pages does not reorder saved records.
- The selection popup is positioned from the selected passage. Comments use ordinary text with `@agent` requests; proposals render deleted/inserted wording in the article rather than silently replacing it.
- Accept publishes wording and citations together, Reject preserves the saved page, and stale proposals require another review. History retains the related discussion and exact saved revisions.
- References/Comments have opaque sticky coverage. Tab and Chat changes preserve article content. Evidence opens the pinned saved excerpt and returns to its context.
- Text width is bounded. Opening Chat is quiet. Model connection belongs in Settings. Source imports and answer-derived drafts require deliberate confirmation/publication.

## Deliberate differences and decisions
**Local settings:** ChatGPT connection/model, Agent Hands/local-folder sources and backup/restore belong to the real local app. Retain them. Prototype's reviewer roles, invitations, delegated actions and notification preferences are not implemented merely because Settings exists.

**Example content and wiki ancestry:** The app seeds two explicitly fictional records, not the full Equipment/Microscope/Centrifuge demo tree. Adding dummy pages solely to mimic screenshots would not deliver those routes. Actual user-created hierarchy must remain navigable; a richer optional demonstration workspace is a separate choice.

**Centering with collapsed navigation:** With both ToCs closed at 1440, the bounded article is centered in the remaining document region, left of the persistent 300 px reference rail. It is not centered in the whole viewport. Keep the width limit; decide whether whole-window centering should reserve symmetric space or whether centering within the reading region is the intended behavior. No automatic change is proposed from geometry alone.

**Filled Chat and unpublished draft presentation:** N5/N6 are authorized functional additions, but the inspected Figma Chat frame does not specify a populated answer/draft layout. Review their current presentation rather than describing it as exact Prototype translation. Autosave, explicit publication and provenance are settled functional requirements; visual treatment can evolve.

**Deferred routes:** Home overview, Maintenance queue, notification activity, profile, review delegation/protection/transfer, raw audio/transcription and true multi-person operation are not reachable in this build. Disabled global controls do not imply those features are complete. Semantic search remains deliberately gated; keyword search is not a substitute for its research claim.

## Built-product accessibility findings
This is a bounded audit, not a WCAG conformance claim. Criteria references: [WCAG 2.2](https://www.w3.org/TR/WCAG22/).

- **Keyboard / focus (2.1.1, 2.4.3, 2.4.7):** Inline citation activation fails as A10 records. Native Tab reaches Comments with a visible 2 px outline. In Chat, Tab advances from the composer to its import control, and Escape closes the drawer and returns focus to Chat. The tab widget differs from the [WAI-ARIA tabs keyboard pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/); the arrow-key issue is not proof that Tab cannot reach either tab.
- **Names, roles and states (4.1.2):** Native AX exposes named buttons, disabled controls and selected tab states. History lacks an accessible dialog name (A11); Search's observed name is correct. Citation role/name alone did not make it keyboard-operable. Full VoiceOver behavior remains untested.
- **Text resize and reflow (1.4.4, 1.4.10):** Controlled 200% text enlargement exposed overlap. This was a diagnostic font-size override, not a verified native browser/OS zoom feature. The 320 CSS-pixel diagnostic exposed off-screen content despite the outer document reporting no horizontal overflow; Tauri's configured minimum ordinary window width is 960. A minimum window width does not settle enlarged-text usability.
- **Text spacing (1.4.12):** A read state was checked with 1.5 line height, 0.12 em letter spacing, 0.16 em word spacing and 2 em paragraph spacing. The inspected body remained readable; the title rewrapped. This does not cover every editor/dialog state.
- **Hover/focus content (1.4.13):** The selection popup is triggered by selection, not hover. Existing native selection tests cover dismissal/positioning, but there was no exhaustive hover/focus-content sweep. Not claimed passed.
- **Contrast (1.4.3):** Calculated rendered text colors against white: body `#202833` 14.86:1, secondary `#697582` 4.70:1, link `#1875be` 4.85:1. The same secondary color against the subtle `#f7f9fb` background is 4.45:1, so muted-on-subtle combinations need checking/correction where actually used. This is a sampled text-color check, not full contrast coverage of every state, disabled control or proposed-change color.

## Suggested sequence and verification
1. S01/S12: fix A1–A3 and A10–A12 as the shared-shell/accessibility batch. Check read/edit/review/Chat at wide, default and compact widths; include real key activation, dialog names, enlarged text and content reachability.
2. S04/S05: implement A4 passage-relative annotation layout, then A5 dedicated revision comparison. Verify note selection, scroll, accept/reject, stale anchors and return to the same page/passage.
3. S03/S09: address A6/A7 search and authoring presentation while keeping explicit source context and publication boundaries.
4. S07/S08 and S04: implement A8/A9 only as separately bounded feature work. Keep transcription, semantic retrieval, maintenance execution and shared operation behind their existing decisions.

## Not reached or not established
No complete test of every one of the 246 Prototype states, no new Figma playback claim, no real media/transcript review, no semantic retrieval benchmark, no role/permission exercise, no cross-platform coverage, and no completed human acceptance. The evidence supports specific findings above and the separately documented native functional journeys. It does not establish full design parity or release readiness.
