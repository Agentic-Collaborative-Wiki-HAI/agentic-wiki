# Native passage review verification — 2026-11-17
This record covers the M1 implementation checkpoint in `app/`, after the foundation was committed. It covers deterministic native checks and a separate live ChatGPT run. It does not claim that the full Figma prototype is implemented.

## Implemented route
Getting started → select a passage within one paragraph → add a comment → reply with `@agent` → inspect the inline deletion/replacement and its thread explanation/evidence → reply for another version or edit the proposed wording inline → accept/reject → inspect the saved revision and conversation → restart. An initial comment containing `@agent` also starts a request. Ordinary comments never invoke the agent. ChatGPT connection and model selection live in Settings, with unfinished comments preserved when returning to the page.

The app owns its discussion and proposal records. Model output cannot publish a revision. Accept writes the reviewed replacement, pinned citations and human decision in one SQLite transaction. Reject records the decision without changing the page or citations. Resolving the conversation is independent of accepting its suggestion. An intervening page revision blocks acceptance and requires an explicitly refreshed candidate.

The interaction was checked against the released Prototype’s [explicit request](https://www.figma.com/proto/fm5zX32mbG13hahShVgJwd?node-id=2621-89154), [inline proposal](https://www.figma.com/proto/fm5zX32mbG13hahShVgJwd?node-id=2621-89285) and [human-edited proposal](https://www.figma.com/proto/fm5zX32mbG13hahShVgJwd?node-id=2621-87499). Connection configuration is a local-app addition. This checks the requested interaction, not full pixel parity or all Prototype routes.

## Limits
- One local operator; no shared identity, permission enforcement or concurrent team editing.
- An old draft is preserved if acceptance advances its base revision. It cannot overwrite the accepted page; a dedicated stale-draft recovery/discard interface remains future work.
- Passage anchors cover a selection inside one paragraph. Changed historical quotes are retained and marked detached; complete anchor migration is not implemented.
- The recording is a seeded transcript excerpt, without real media import/playback or transcription.
- Search, artifact intake, maintenance execution, portable export/restore and the rest of the prototype are later workstreams. D6–D8 remain deferred.
- No Figma writes or remote publication are part of this checkpoint. Unrelated design records are excluded from its commit scope. `TODO.md` also contains a pre-existing Showroom change and is left uncommitted.

## Follow-up context audit
A revision request includes the exact pending proposal’s wording and explanation, disclosed in the thread’s Context sent to the agent details. The backend rejects a different prior ID or changed prior text before saving, and rejects an obsolete parent before starting inference. A previous proposal is a draft to revise, not evidence; the new result may cite only the source excerpts disclosed for the current request. Follow-up requests retain the pending proposal’s pinned evidence if the source has since advanced. Initial requests use the page’s pinned citations and directly attached recording paragraphs, capped at eight source passages; exceeding that bound produces an error, not silent truncation or wider retrieval.

## Native test startup
The WebDriver request timeout is longer than the driver’s script timeout. Initial page readiness may retry a timed-out read against the same still-running process within a bounded window; interaction commands are not replayed automatically. Both native suites pass after this change, and the ordinary desktop build is restored with the test feature absent.

## Reproduction and data isolation
Run `WIKI_RUN_LIVE_CHECK=1 npm run test:review:live` from `app/` only when live subscription verification is authorized. The native test build uses a temporary wiki and the signed-in app’s protected connection in place. It does not export credentials, capture account screenshots or copy working page content into the test. Test results and fictional model wording are ignored local artifacts. Ordinary builds ignore both test environment switches and have no WebDriver or candidate-injection command.

## Selection action follow-up
The Comment action is a compact floating popup positioned from the selected text’s browser range. It appears above the visible selection when there is room, otherwise below, and stays within the article viewport. Scrolling or resizing recomputes its position; an offscreen selection hides it. Escape, an outside click or opening the comment composer dismisses it. It is absent while editing, in Settings and in global Chat. Clicking Comment preserves the selected quote for the thread.

The native WKWebView check selects part of the booking sentence, verifies a compact fixed popup next to the actual highlight without changing the paragraph position, scrolls the article and checks the new placement, then dismisses with Escape. The same run completes the comment, inline review, evidence, human revision, accept/reject, history and restart checks. The eight frontend tests and production build also pass. This follow-up uses fixture candidates; no additional live model request is needed for popup placement.
