## Current Design Basis
- A recording is one typed record with audio and a linked transcript presented as parts of that record. Do not require separate audio/transcript pages or duplicate navigation entries in the current working set. This does not finalize storage, deletion, or component-addressing semantics.
- Media format narrows available artifact types but does not determine evidentiary role. The audio upload offers Primary recording and Audio note; a type is required before submission. The user removed Choose later on October 22 to keep the system strictly typed. An audio note can contain thoughts generally, including a spoken summary.
- Chat is the intake surface for material without a chosen location; the user withdrew the separate neutral inbox/folder idea on October 22. Attachment does not publish material. A structured intake card requires an artifact type and an explicit Add action, with agent-selected placement showing its suggested destination before that action. This chat intake is agreed but not yet drawn. The upload's optional transcription control is presented as a switch.
- Persistent chat occupies its own sidebar, closed by default unless it is needed to explain the interaction. A top-right sidebar icon opens and closes it in the prototype. References and Comments remain tabs in the document margin; chat does not join those tabs. The article and its margin stay together as chat opens or closes. The chat composer and attachment affordance are visual wireframes; chat intake is not yet interactive.
- Main navigation follows page hierarchy. Linking, citing, deriving from, and organizing under remain different relationships. Recursive relationship-tree experiments are retained outside the current navigation.
- Keep the title prominent in intake, followed by the file, human description, optional transcription, and an explicit submit action. Show the unsaved draft in navigation. Checking is a mode of the recording's normal transcript view, with a clear scope and a check action below the transcript.
- Show the complete transcript by default as scrollable page content. Place compact type/upload attribution and the description below the title, rather than in a metadata sidebar. Keep AI authorship and checking status visible; expose filename, technical metadata and the checking record through Details. Remove repeated type labels and explanatory text that restates the visible structure. Waveform display is not needed for this initial view.
- A passage link should open the recording, scroll to and highlight the passage, and cue its audio timestamp without autoplay. A whole-recording link opens the normal view. This behavior is agreed; interactive passage linking is not yet implemented in the fixed-state prototype.
- Human edits normally follow edit permission. Agent changes to shared prose require review. Authorship, human editing, acceptance, and transcript checking remain separate facts. Protected-page behavior is a possible stricter rule, not a prescribed permissions matrix.
- Comments can be anchored to text. Shared threads invoke the agent only when a message explicitly tags `@agent`; ordinary teammate replies do not trigger it. One-to-one chat remains a separate conversation. Accepting a proposal and resolving a discussion are separate actions.
- Suggested changes appear as inline deletions and additions within the document. Each replacement has an attached margin thread containing its author, evidence link, Accept/Reject controls and replies. Revision requests happen in that thread through `@agent`. Human-authored and human-edited suggestions retain their distinct attribution.
- Reused text has a single centered handle for its range, subtle highlighting, and a linked source label. Editing opens the source in context; it does not silently edit a local copy. Citations, links, and human discussion are distinguishable.
- Provide a version-history page as a common artifact pattern. Comment/discussion versioning and treating discussions as independent artifact types are deferred. The history view is agreed but not yet drawn.
- Live transclusions reflect source changes. Generated documents must cite the material they derive from. A citation to a specific passage may need a notice when that passage changes; the notice behavior and treatment of affected derived documents remain unresolved. A source change does not itself authorize rewriting shared prose.
- Primary evidence cannot be replaced in place. Removing it and adding another piece creates a new artifact identity. A workflow that maps the new evidence to the deleted evidence's former role and reprocesses dependents is deferred; deletion's effect on existing citations remains unspecified.
- Restore the earlier wireframe styling, following the user's October 22 feedback: full-width header, quiet page tree, readable body text, plain metadata, compact contextual panels, and lighter secondary actions. Use drawn vector controls rather than emoji or symbol-font buttons. The comparison page remains structural input; its visual styling is not the direction for Workshop.

## Open Questions for Review
These are unresolved design choices, not approvals or implementation instructions.
- Q1 resolved October 22: the entire transcript is visible by default, with scrolling for its full length. Citations and compact transclusions need not display the whole transcript.
- Q2 behavior resolved October 22: open and highlight the passage and cue the corresponding audio timestamp without autoplay. The exact address format and link-creation interaction remain unspecified.
- Q3 current direction: retain Primary recording and Audio note and require type selection. Choose later is explicitly removed. No separate evidence-role selector was introduced.
- Q4 direction resolved October 22: attachments remain conversational until an explicit Add action in structured chat intake. Agent placement shows a suggested destination first. The latency and second-guessing concern is saved as native Figma comment #3 on a5, prefixed Agent:, rather than as a canvas object.
- Q5 direction resolved and implemented October 22: chat is a separate sidebar; References and Comments share the document margin through tabs. The desktop layout uses 1800-pixel frames, with the article and margin centered in the available area when chat is closed. A shared header toggle controls chat visibility across the current desktop screens. Narrow-screen behavior remains unmodeled.
- Q6 direction resolved and implemented October 22: use inline suggested edits, with a separate margin conversation for each edit. The current sample replaces one paragraph and therefore has one suggestion thread. The review route demonstrates a tagged revision request, an agent reply and a teammate reply without another agent response. Visual acceptance remains pending.
- Q7 history direction resolved October 22: use a version-history page for artifacts; defer comment/discussion history. The relationship between a transcript revision and its checking status still needs definition. Checking must not imply that the current procedure or a derived summary has been verified.
- Q8 partly resolved October 22: transclusions update with their source; derived documents cite their sources; primary evidence is immutable and a different upload receives a new identity. Passage-specific citation-change notices are a provisional direction. Handling broken citations after deletion and the effect of source changes on derived prose remain unresolved. Replacement/reprocessing is deferred.
- Q9 scope confirmed October 22: F1, F4 and F8 are already committed and still incomplete. Finish their relevant alternatives before broadening the slice. This is a completion question, not a new choice of workflows.

## Source Review and Limits
The reviewed meeting material supports simple page hierarchy and consideration of a recording as a unit. The user's current instruction adopts the latter for this consolidation. Folder schemes, automatic filing, agent scope/authority, always-open assistant chat, and exact evidence-display defaults were not promoted into decisions. The first consolidation borrowed navigation and panel structure from the comparison page. Following October 22 feedback, Workshop returned to the earlier visual treatment: the full-width header, quieter navigation, plain properties, and compact contextual panels. Browser-style app tabs and additional back/forward controls were not introduced.

The current prototype contains 42 screens across routes, outcomes, patterns, overlays and the launcher, including two on-demand file-detail states, plus reusable chat-sidebar and sidebar-toggle components. It uses fixed sample states, with working chat open/close behavior. Real file selection, typing, playback, passage-link scrolling/highlighting/cueing, persistence, chat submission/intake, alternate upload-type submission, partial checking and additional repeated agent-revision rounds are not implemented in this current presentation route; their prior explorations remain in Scratchpad. Navigation between independent sample routes does not simulate a persistent application session. This boundary should be stated during evaluation, rather than treating every visible control as a functioning feature.
