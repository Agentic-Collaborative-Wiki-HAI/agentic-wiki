# S07 · Artifact intake and source imports
Active spike: `app-artifact-intake`. Owner: Aslan’s agent in this implementation conversation. The user authorized local source-folder settings and Agent Hands imports for Meet transcripts on 2026-11-17. [Build map](implementation-planning.md) · [Tasks](app-artifact-intake.todo.md).

Continues from: docs/active-spikes/implementation-planning.md

## Current batch
Import existing transcript or note text before implementing local transcription. Settings owns an optional local source folder and an optional Agent Hands Drive tool/account/folder connection. Add artifact and Chat share a preview/confirm importer. A local folder contains actual UTF-8 text exports; Google-native `.gdoc` shortcuts require the Drive export adapter. Start with TXT, Markdown, SRT and VTT text plus native Google Docs exported as text. DOCX/PDF parsing, binary media import/playback and local transcription remain later work.

The app invokes fixed Agent Hands read/export commands, never commands generated by the model. Reuse the selected provider runtime’s account in place; do not copy credentials, expand scopes or read private vault policy into the app. Meet folders can contain per-meeting subfolders; browsing verifies ancestry under the configured root. Local listing reads only the selected folder’s direct files. List results are explicitly bounded. Export full document text rather than the CLI’s truncated read preview. Import and settings data stay in the private app database.

Preview makes source, title, content type (transcript or notes), attachment parent and existing-import status visible. Confirm stores the original export bytes and provenance with a published document revision in one transaction. Cancel creates no object. Reimporting identical content opens the existing object; a changed source requires explicit confirmation of an updated copy, preserves prior revisions, and refuses a stale preview. Imported text remains content, never executable instructions. Human-authored notes and AI summaries are not labeled as verbatim transcripts by inference. A Meet document containing both notes and transcript remains a complete notes document with the original section labels; per-tab extraction is deferred.

## Current implementation and limits
`app/src-tauri/src/imports.rs` owns snapshot/revision transactions; `sources.rs` owns bounded local and Agent Hands reads; `desktop_imports.rs` holds short-lived preview tokens. Frontend settings and import dialogs use specific commands rather than general shell/filesystem access. Source identity is provider plus canonical local path or Drive file ID. Imported documents have explicit transcript/notes metadata, separate from the existing page/recording storage family.

The app stores source bytes with the revision, not as a pointer that depends on the original staying accessible. Changed-source refresh replaces current text only on confirmation, refuses an intervening human revision, and preserves old revisions and their citations. Identical source bytes open the current copy without replacing local edits. A renamed or moved local file is a different source identity; there is no relinking workflow yet. Imported sources appear in navigation and can optionally link to a page for the existing bounded evidence context.

Current bounds: UTF-8 text up to 1 MB; first 500 direct local entries; one Agent Hands listing page with a visible partial-results notice; Google folder ancestry up to 16 levels; 60 seconds per CLI command; previews expire after 30 minutes. Errors and cancellation create no visible artifact. No automatic source writes, background sync, audio processing or model invocation occur on import. Current model-context limits can reject a long linked transcript; retrieval remains S09 work.

## Later scope
The remainder of this brief records the media intake/playback route for a future batch, not acceptance criteria for the text-import checkpoint.

## Outcome
Drop or choose a real recording in Chat or Add artifact, confirm what it is, keep one canonical artifact, and play it without losing the page context.

## Scope
Implement file chooser/drop handling, temporary attachment state, editable title/description, explicit type confirmation, file persistence and audio playback/seeking. Support Primary recording versus Audio note, adding without a transcript, non-audio attachment behavior and idempotent retry. Preserve original bytes and checksums; derived media files are separate.

Out of scope: No cloud object store, arbitrary recursive disk import, automatic semantic classification accepted without confirmation, or “click the title to skip Add artifact” shortcut. Unsupported formats must be explicit rather than a fake success.

## Acceptance criteria
- Choosing or naming a file does not create the artifact until the user confirms; cancellation leaves no orphan visible object.
- Retry after a partial failure cannot create two artifacts for the same import command.
- The original source remains available after moving/deleting the file outside the app, under the proposed managed-copy policy.
- Audio remains accessible while reading a long transcript; citation jumps reach the intended time range and Close returns to the caller.
- Chat intake and Add artifact use the same object and lifecycle rather than independent scripted copies.

## Automated and integration checks
Disposable-file tests cover duplicate filenames, interrupted copy, missing file, bad format, traversal paths and failed database commits. Real Mac tests cover drag/drop, file dialogs, supported codecs and audio seeking.

## Human QA
Try both intake entry points with a short non-sensitive recording. Inspect title editing, cancel/remove, type confirmation and audio controls while scrolling.

## Risks, choices and recommendation
Copying imports uses more disk space but makes a local workspace portable and reliable. Recommend managed originals plus clear size/error feedback; external-path references would need a relinking workflow. Codec conversion and limits require measurement, not guessed promises.

## Independent work and gates
Intake and playback work without model access or transcription. Completing the actual Chat-to-transcript journey requires S06 orchestration and S08 processing, but the app must also support the no-transcript route.
