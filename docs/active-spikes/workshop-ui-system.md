# Workshop UI System
Opened 2026-10-22. Slug: `workshop-ui-system`. Related working flows: [Wireframe Workshop](wireframe-workshop.md).

## Purpose
Turn the current Workshop's repeated visual patterns into a maintained Figma system, from foundations and small controls through composed panels and complete interfaces. Preserve the established quiet Roboto, blue-gray, low-fidelity appearance. The purpose is consistent behavior and easier future edits, not a visual redesign or new product scope.

## Scope
The maintained system covers the current F1, F4, F8 and selected citation/reuse screens. Historical Scratchpad alternatives and teammate pages remain unchanged. Existing shared library assets are references and reusable foundations; avoid changing their appearance for other users of the file. Foundations, specimens and source components live on the user-created [Component Library page](https://www.figma.com/design/fm5zX32mbG13hahShVgJwd/Agentic-Collaborative-Wiki?node-id=593-3103), using the Workshop namespace. Working interfaces remain on Aslan's Workshop and reference these same source components.

### Foundations
Define semantic surface, text, action, border and status colors; a text hierarchy; and spacing, corner and control-size tokens. Reuse compatible existing primitives. Typed objects and source relationships express provenance; standalone evidence-tier labels are not part of the visible interface. Keep media format distinct from human/machine authorship. Do not introduce dark-mode work or a new theme in this slice.

### Small controls
Provide shared buttons, icon controls, links, margin tabs, status labels, input fields, switches and page-tree rows. Use meaningful variants and exposed text/icon properties. Keep production behavior beyond the existing prototype outside scope.

Compact actions pair an icon with a short verb-and-object label. Their smaller dimensions are intentional: 24 px height, 14 px icon, 12 px label and tight padding, with width fitting the words. Quiet is the default treatment; Outline and Filled variants provide stronger affordance when needed. Each style supports Standard/Destructive intent and Default/Hover/Pressed/Focus/Disabled states. The editable source grid is the review surface for this family. Remove file uses the Filled destructive treatment with a red icon. Play/pause, close controls and page-tree disclosure arrows remain icons.

The component library describes the logical control system beyond the combinations currently used in screens. Comparison sheets use instances, with each style or persistent value grouped into a row and interaction states across columns. Component sources contain the corresponding editable masters. Button emphasis and destructive intent, icon selection, field format and validation, navigation depth and selection, and switch value are independent dimensions. Focus has a separated ring; hover and pressed states have distinct treatments. Status labels remain noninteractive.

### Composed patterns
Build the header and navigation, References/Comments margin, reference and discussion content, suggestion threads and decisions, upload controls, recording/transcript presentation, and reused-content treatment from shared parts. References and Comments use one tab treatment and consistent container geometry. Their contents retain their distinct roles. Switching tabs changes only the local sidearea, preserving the current article, editing state and discussion thread. Populated Workshop states use independently scoped visibility variables; empty margins use the shared interactive component. Chat uses a full-height overlay drawer covering the right of the header and margin without dimming or reflowing the page. Its toggle retains the same screen position.

Pages navigation is 280 px wide, followed by a separate 180 px On this page column aligned with the top of the body content. References/Comments occupy a 400 px sidearea at the right edge, separated through whitespace rather than a tinted panel; their tabs begin directly below the creation controls. History views omit both contents navigations and creation controls; the selected event’s associated discussion appears on the right beside its contextual inline diff. The header groups the wiki title, full breadcrumbs and 375 px search on the left, with Notifications, Profile, Settings and Toggle chat controls on the right. Notifications uses a compact bell-and-label action and opens a dated preview linking to the transcript awaiting review and a pending suggested edit. A thin footer finishes the desktop shell. Recording screens prioritize the full transcript at 22 px with 34 px line height, with playback below. The intake description is taller and includes a bottom-left resize grip and counter; its 2,000-character limit is provisional.

Transcript editing retains the reading view’s timestamps and speakers, with compact audio controls directly beneath the transcript and no artificial blank spacer. Cancel precedes Save transcript on the right. The prototype models play/pause and three timeline positions; it does not contain a playable recording. The shared audio states live on the Component Library page.

Mentions use a squarish pale reddish-purple pill for agents and a round lemon-green pill for people. Profile/chat destinations for mentions remain future behavior. Links use blue without a resting underline, with a separate underline treatment on hover/focus and a visible focus ring. The chosen link color (#1875BE) measures 3.06:1 against primary prose (#202833), 4.85:1 against white and 4.60:1 against the subtle surface. These measurements support this treatment under WCAG; they are not a whole-interface conformance assessment.

Shared creation controls place + Add page and + Add artifact in a transparent bar below the navbar, above the page body and margin. Edit page and Page history align with the page title. Editing keeps the title editable and hides creation actions and routine attribution. The shared editing bar starts below the title and becomes sticky on scroll. Editing sits on a line above the formatting controls; Track changes follows those controls, with compact Cancel before Save/Submit actions on the right. Transcript editing uses a variant of the same component. Recording pages use Edit recording artifact at page level, with Edit transcript and Mark transcript as reviewed beside the transcript heading. Reviewed/revised attribution stays beside AI-generated attribution; both Reviewed by and Revised by link to transcript history, including Reviewed by attribution in reference cards; Edited by links to page history. Artifact type is selected inside the upload modal after a file is uploaded. Empty intake hides description, type and transcription controls and has a disabled Add action. Removing an unsaved upload loops back to that initial state. Upload file uses a bordered button and Add and transcribe uses the solid primary treatment. The Generate transcript off branch saves the recording without a transcript and permits later generation through a compact action inline with the no-transcript message. Processing appears above playback where the transcript will appear. Cancel and Close use modal overlays to return to the originating screen. Recording pages show filename alongside playback and uploader/date beneath the title. Repeated Details metadata and Shared with lab are removed from active screens; the former Details overlays remain reference material.

Each discussion has one bordered card enclosing its messages, suggested edits and reply composer. Messages retain avatar, name and timestamp; the agent uses a toy-robot avatar. Cancel and Reply are grouped inside the card and right-aligned. A compact Resolve thread action appears at the top. Resolved threads leave the active margin and remain accessible in history. Anchors highlight text ranges rather than entire paragraph blocks; block boundaries do not define the intended selection boundary. A requested agent revision appears as the agent's reply with per-suggestion Accept/Reject controls. Reply fields accept the next message; @agent is part of the message, not a separate button action. Normal editing and Track changes have separate prototype states, and a tracked human edit enters the existing human-review pattern. Selection-menu examples offer Add comment while reading and Add link, Add citation, Add margin note and Add comment while editing. The editing menu connects to four left-to-right branches, j1–j4, showing entry, completion, insertion and a saved result. Link uses a single destination input near the selection without creating a reference note. Citation searches the wiki or accepts a URL/DOI, with manual source details available; whole-source citation is the default and passage selection is optional. Margin note creates a numbered aside and supports inline links during creation and editing. Comment posts a range-anchored discussion in the margin. Close/Cancel return to the unchanged selection. Fields, search and selection are simulated; each branch demonstrates one independent addition rather than accumulating content across branches.

References use shared bordered citation and explanatory-note variants, with numbered link anchors for both. Numbers identify notes: repeated use of the same note reuses its number, while distinct notes about different passages of one source get distinct numbers. A note can also cite a source generally. Author/year information is optional; external citations may carry structured URL, DOI or print-source information. Page and artifact history views expose changes and review events. Collapsible endnotes provide a continuous list, citation-only filtering and return links. Conversation source links use descriptive labels rather than endnote numbers. Proposal scope beyond a discussion’s original anchor, superseding earlier suggestions and optional decision comments remain discussion choices.

### Interfaces
Integrate the shared system into the maintained screens, preserving their sample copy, workflow decisions, native frame identities and positions, prototype destinations, and native comments. Keep the left-to-right branching canvas arrangement. The system is not complete merely because a specimen page exists; the actual working flows must use it.

The Lab opens Wiki Home, which connects the maintained routes through page links, pending work and recent activity. A gold Prototype only control returns to the optional routing frame. The maintained inventory includes retained references, two selection-menu examples, four selection-authoring branches, Profile, Settings, an audio-note result, a focused acceptance-history view and artifact-dialog overlays. Page creation, recording without transcription, artifact editing, human-revised transcript and history states extend the existing flows. All pre-existing screen roots retain their identities and positions. No application implementation is implied by the clickable prototype.

Profile shows the member's name, avatar, a Private wiki indication marked Only you, and example activity links into history with dates and times. It omits both contents navigations and the redundant bottom Settings action. The private wiki is represented as a personal place for drafts and notes; its internal route is not modeled. Personal Settings demonstrates two notification switches. Both are accessible from the shared header and return to Wiki Home. Chat opens as an overlay drawer on wiki screens. Profile and Settings omit both Toggle chat and the sidebar, while preserving the wiki chat state for returning to the wiki. Its shared intake stages distinguish an unsent attachment from a sent message and from an artifact added to the wiki: attach or remove a draft, send it, choose Primary recording or Audio note, review the suggested destination and transcription switch, then confirm Add artifact. The message composer groups a compact + Add file to chat action on the left and a filled Send button on the right; the separate upload box is omitted. Closing chat preserves its current stage. Chat intake shows the proposed destination before confirmation. Audio-note routes include transcript and editing states; this is not proof of complete processing support for other file types. File uploads, messages, transcription and notification settings are simulated interactions.
